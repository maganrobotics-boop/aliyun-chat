原始失败工作流：`38541493993`，job `115777086432`。

## 根因与最小修复

实际 Actions 日志及本机真实 Chromium 均复现：原测试第 175 行点击“开始任务”超时，命中底部导航“进度”按钮。

根因位于测试 HTTP 服务器：只声明 HTML/JS 类型，遗漏 `.css`，导致两份页面样式以 `application/octet-stream` 返回，被 Chromium 拒绝加载。JS 仍添加 `workspace-fullscreen-page`，但配套全屏布局完全未生效。

原始 1280×900 复现测量：任务按钮 y=832.80–876.80，导航 y=830–900；任务框已滚到最大值 562px，页面滚动 1850px。内联 `.main` 的 84px 底部留白不覆盖位于其外部的 dialog；普通 `show()` 打开的 dialog 无法越过固定导航。增加主内容底部 padding 或强制点击均不能修复这个测试环境问题。

实际 `workspace-r4.css` 已包含完整布局约束：

- 全屏任务框固定在视口内，层级 80，高于导航的 40。
- 全屏任务框打开时隐藏底部导航，背景 body 禁止滚动。
- 内容在任务框内滚动，底部保留 36px；普通页面底部留白及导航高度计入 `safe-area-inset-bottom`。

本次只修复测试资源响应类型，并增加样式响应/加载断言及真实点击命中验证。生产 HTML、JS、CSS、API、课程内容、字幕、依赖和部署脚本均无修改。曾在隔离分支验证原生模态方案；发现 MIME 根因后已完整撤回，保留既有全屏交互。

样式正确加载后，原测试访问的顶栏登录入口实际被隐藏；改从可见底栏“我的”进入登录，保存资料也改为真实按钮点击。刷新从受支持的个人/进度页执行，避免已明确退役的 `#courses` 入口重定向到 `/learning`；不伪造或覆盖新的学习页面。管理员端补齐真实“协议审核”标签点击，原有签署/审批断言全部保留。
